# Adversarial Friends 0.2.0 Dogfood Design

## Goal

Exercise the published `adversarial-friends==0.2.0` package as an external
user would, across all four shipped modes, and produce an evidence-backed
reliability report. The run tests orchestration, participation, persistence,
halt/resume, exit semantics, and report quality. It does not fix defects in
the same pass.

## Test subject

Use the installed `/Users/tim/.local/bin/afriend`, after verifying it reports
`afriend 0.2.0`. Do not invoke the checkout with `uv run`.

Use one compact, real artifact for every mode so the outputs are comparable:

`docs/superpowers/reviews/2026-08-29-staged-hardening-plan-review.md`

This is a 760-word review of another artifact, the highest-value case in the
shipped skill. Every run must use normal discovery rather than an explicit
roster, because default reviewer discovery and lens assignment are part of
the behavior being dogfooded.

## Bounded progressive ladder

Run the modes sequentially. A mode begins only after the preceding run has
produced parseable durable artifacts.

1. **Report:** one critique round using default discovery. This establishes
   the participation baseline and verifies the stdout run-path contract.
2. **Crossexam:** two rounds with `--merge orchestrator`. The expected first
   exit is `10`. Review `REQUEST.json`, record only defensible merges (an
   empty merge set is valid), write `RESPONSE.json`, and resume. Verify that
   round 1 is not dispatched again and that the ledger does not duplicate its
   claims.
3. **Gate:** two rounds. Exit `1` is expected when surviving non-advisory
   claims need resolutions; exit `0` is valid only if every such claim clears
   through the mode's own semantics. Do not invent resolutions merely to
   obtain a zero exit code.
4. **Loop:** at most two iterations of two rounds each. Exit `11` is an
   expected bounded result when the run has not converged; exit `0` is valid
   only when `run.json` and the report say the convergence condition was met.

Every run sets `--max-friends 4`, `--require-friends 2`, and the normal
900-second per-friend timeout. Crossexam and gate receive a 3,600-second wall
clock. Loop receives 5,400 seconds. No run uses
`--allow-unsandboxed-friend`, `--unsafe-extra-args`, or `--include-self`.

## Why the run takes 45–90 minutes

The shipped skill records a measured single-friend critique at roughly six
minutes. Friends within one round run in parallel, so four friends cost about
the duration of the slowest friend, not four times six minutes. Rounds and
loop iterations are sequential, however.

The bounded call envelope is approximately:

- report: `4 friends × 1 round = 4` calls;
- crossexam: up to `4 × 2 = 8` calls;
- gate: up to `4 × 2 = 8` calls;
- loop: up to `4 × 2 rounds × 2 iterations = 16` calls.

That is up to 36 primary friend calls, plus startup, schema repair, merge
adjudication, persistence checks, and variance in the slowest CLI. At six
minutes per parallel round, the nominal critical path is about 54 minutes.
The 45–90 minute estimate allows faster short-artifact responses and slower
authentication, queueing, or local-model behavior. The unbounded defaults
could exceed two hours because crossexam may use three rounds and loop may
use five iterations.

## Evidence collection

For every run, capture:

- command, start/end timestamps, wall duration, stdout, stderr, and exit code;
- `run.json`, `report.md`, and `claims.jsonl` validity;
- every friend's status, duration, schema/read-only/effort declarations, and
  actual confinement record;
- critique and verdict counts by round;
- downgrade, auth-abort, repeat-failure, ceiling, and quorum signals;
- whether the report's prose matches the ledger and process exit.

Do not kill a quiet run while its 30-second heartbeat continues. Keep the
runner's stdout unmodified because it must contain only the run directory.

## Error handling

- Exit `10` from the orchestrated crossexam halt is expected and must be
  followed by inspected adjudication and resume.
- Exit `1` from gate is expected when claims remain unresolved. The report,
  not a desired zero, determines correctness.
- Exit `11` from the bounded loop is expected if convergence needs more than
  two iterations.
- Exit `12`, every friend failing, an authentication abort, a traceback, a
  missing report, malformed ledger data, or disagreement between exit status
  and persisted state is a dogfood defect. Preserve the run and diagnose it
  with `afriend doctor`; do not weaken sandboxing to continue.

## Acceptance criteria

The ladder passes as a reliability exercise when:

1. the released binary, rather than the checkout, runs every stage;
2. at least two friends produce usable critique output where quorum applies;
3. each terminal or halted path writes a parseable report, run metadata, and
   ledger whose observable state agrees with the exit code;
4. orchestrator resume neither redispatches nor duplicates round 1;
5. gate and loop return their documented semantic exits;
6. reports disclose partial participation and security downgrades rather
   than presenting them as success; and
7. all observed defects and limitations are ranked with concrete evidence.

Individual adversarial findings do not make the harness fail. The harness
fails when it loses, misstates, corrupts, or cannot reproduce those findings.

## Deliverable and scope boundary

Write the synthesized result to
`docs/superpowers/reviews/2026-08-30-v0.2.0-dogfood-report.md`. Separate tool
defects from findings about the reviewed artifact, combine semantic duplicate
findings only in the presentation, and record which friends did not
participate.

Do not modify runtime code, resolve gate findings, or prepare `0.2.1` during
this exercise. Any verified defect becomes a separately designed and tested
follow-up.
