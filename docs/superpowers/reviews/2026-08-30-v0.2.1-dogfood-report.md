## Dogfood regression and TDD evidence

New regression:
`tests/test_task10_dogfood_regression.py::test_report_resume_can_finish_after_spending_exact_call_budget`.

RED reproduced the live behavior exactly: two fake reviewers spent an exact
two-call budget, report mode halted for an orchestrator response, and resume
returned exit 11 with `afriend: max-calls`.

Root cause: `cmd_run` checked whether the *next critique round* fit the call
and wall-clock budgets before entering the branch that consumes an existing
orchestrator response. A non-judging report resume has no next critique round.

Fix in `3e80fde`:

- do not run critique-only call/time preflight for the first resumed iteration;
- let resumed judging paths enforce their own actual judging-round budgets;
- re-check cumulative wall time immediately after applying the response, so
  the existing multi-resume wall-clock contract remains intact.

Evidence after the fix:

- new exact-call report-resume regression: GREEN;
- existing multi-resume wall-clock regression: GREEN;
- 68 affected orchestrator/resume tests: GREEN;
- Ruff, focused strict mypy, 777-line gate, and `git diff --check`: GREEN.

The original live run is intentionally preserved as failure evidence rather
than rewritten. A second external-provider retry was not made after the defect
was isolated; the deterministic end-to-end test exercises the corrected
resume path without another paid provider call.
